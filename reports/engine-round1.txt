KNOWN LIMITS, INTERPRETATIONS AND DEVIATIONS
- Model correctness only. No federation-compliance claim. Practice seeding —
  not federation-compliant. This harness is not the CourtKit-density six-screen UI.
- No hard HiGHS size ceiling is claimed. The representative fixture is a measured
  supported example, not a universal runtime guarantee. Only Node and Chromium
  were tested. Production UI should supply solve budgets and expose statuses.
- Team/leg indexes are zero-based. Events containing any pin or ban retain slot
  identity: unconditional fastest-A relabelling could violate C8. Unlocked events
  are relabelled fastest-first and revalidated. stats.tie is the pre-relabel hash
  objective; costCs is raw time, totalCs includes three split adjustments.
- The independent oracle enumerates ordered four-swimmer assignments, keeps the
  cheapest ordering for each member set and memoizes remaining subproblems. This
  differs from an entirely naive enumeration for speed, but uses no solver/model
  helpers, validator, MILP, or lower-bound pruning. Its bitmasks are test-only for
  the specified small instances; it is not a second production engine.
- Hash mod 10 can collide. Reproducibility is verified for fixed input ordering,
  seed, one thread and pinned runtime, not a proof of a unique optimum or identity
  across future solver/browser versions. Timing is excluded from solution JSON.
- C4 is literal: already-over-cap individual entries make the instance infeasible.
  At the cap, available relay capacity is zero. Without pins and with nonnegative
  caps, empty fielding is feasible and can be optimal if nobody is eligible.
- Sequential accepted teams are retained and consume capacity for later events.
  It reports feasible, never whole-meet optimal. Savings require the same fielded
  team slots; differing coverage is shown as team/weight difference, not seconds.
- Relaxations identify single-family feasibility restoration, not an IIS/minimal
  conflict set. Eligibility relaxes sex/mixed balance and missing times; age bands
  relaxes both individual and sum ages. Synthetic diagnostic times are not returned.
  Several simultaneous causes may require more than one relaxation.
- Solver time budget spans three primary stages; JavaScript model construction
  overhead is outside it. Node budgets are per stage. Each diagnostic re-solve has
  its own budget. Limited output is validated and never labelled optimal.
- Circle seeding implements both 2 and 3 heats (the data model allowed 2 but the
  brief only illustrated 3). NT timelines require an explicit estimate. Booking
  is same-day only. Expected/pessimistic factors are fixed at 1.0/1.05.
- A G6 expected value was corrected during development: specialist assignment
  gives 8,220 cs, not the initial hand estimate. Independent oracle reconfirmed it.
  The PRNG was improved to cover all roster sizes and multi-slot events; the final
  run records that distribution. No engine-freeze checkpoint has occurred yet.
- No tier/license enforcement is present. Future tier flag is demonstration-only;
  suggested EUR 50–80 per-club annual pricing is unvalidated.
