PROCESS / REPRODUCTION
  npm ci
  npx playwright install chromium
  npm test
  npm run test:ui
  npm run verify:browser

verify:browser builds first, starts Vite preview as a hidden managed child on a
free local port, polls readiness with a deadline, runs both browser suites with
90-second per-suite deadlines, writes raw reports, and stops preview in finally.
It does not wait for a foreground Vite server to exit. The initial manual smoke
preview was also started as a hidden background process, never blocking exec.

The final run executed engine Node gates, UI unit gates, production build, engine
browser gates, and UI browser gates sequentially to avoid load skewing timing.
Raw files: gates-node.txt, gates-ui-unit.txt, build.txt, gates-browser.txt,
gates-ui-browser.txt, gates-print.txt. Screenshots cover all screens, mobile and

MONETIZATION / HONEST LIMITS
Free: roster, setup, sequential single-relay solve, basic lineups.
Pro: whole-meet solve, savings, heat sheets, circle settings, timeline, branded print.
THIS IS A DEMO TIER FLAG AND FEATURE GATE, NOT REAL LICENSE ENFORCEMENT.
No payments, accounts or license cryptography. Product guards are tested at the
action boundary, but do not prevent someone from modifying browser code, changing
the tier flag, or using the separate diagnostic engine lab.

- HiGHS 1.15.4 is the shipped engine. No fallback. The representative size is a
  measured case, not a promised maximum. UI engine budget: 8 seconds per solve;
  total Worker deadline: 30 seconds including comparison/diagnostics. Larger or
  difficult instances can time out. Only actual solver status is displayed.
- Practice rules check the specified mathematical model, not federation rules.
- Heat sheets use this club's solved relay teams. The fixed spec allows 1–3 teams
  per event and 4–10 lanes, so UI events currently fit into one heat. Circle
  settings are supported but do not affect those single-heat cases. The engine's
  multi-heat/circle behavior is covered by G9. No opponent-entry UI was added.
- Timeline includes fielded relay heats only. Pessimism is fixed at 1.05 to match
  the frozen engine; final heat/event gaps count. No individual events, warm-ups,
  breaks, fatigue-spacing or coupled scheduling. Same-day booking only.
- UI input guards require nonnegative start adjustment smaller than recorded
  splits. Import revalidates lineups and objective totals but is not a certificate
  that an imported optimal-status label is mathematically proven.
- localStorage is browser/origin specific. Storage-denied edits stay in memory
  with a visible export warning. Export backups; no multi-tab live merging.
- Print stylesheet only. Saving PDF uses the browser; no PDF library in the app.
